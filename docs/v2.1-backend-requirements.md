# v2.1 backend requirements

What `api.fondeks.com` must add for the v2.1 "Choose" features to light up. The
client (`fondeks-client`) already reads every field below and falls back to
**"Bilinmiyor"** (or hides the row) where it is absent, so these are additive —
nothing here is a breaking change, and shipping them in any order is safe.

Field names are the JSON keys the client reads (see `src/lib/fondeks/types.ts`,
`choose.ts`, `compare.ts`). Percentages are **numbers in percent** (e.g. `62.4`
means 62.4%), matching the existing `y1`, `managementFee` convention. Use
`null` for "not published", never `0`.

---

## 1. Fund object — new optional fields

Returned on **both** `GET /funds` (each list item) and `GET /funds/{code}`
(the `fund` envelope). All optional.

| Key | Type | Meaning |
|---|---|---|
| `ter` | `number \| null` | **Toplam gider oranı (TER)**, % per year — full cost incl. management, custody, audit, transaction. The figure BiFon already computes; reuse that engine, don't rebuild. |
| `netReturn` | `object \| null` | **Stopaj sonrası net getiri**, % by window: `{ "daily"?, "w1"?, "m1"?, "m3"?, "y1"? }`. Gross return less the withholding the holder actually pays — must account for fund type and holding-period brackets (equity funds often 0%). Any subset of windows is fine. |
| `realReturn` | `object \| null` | **TÜFE enflasyonundan arındırılmış reel getiri**, % by window, same shape as `netReturn`. Needs the official CPI series (see §4). |
| `categoryPercentile` | `number \| null` | Fund's standing in its own category over the **1-year** window, **0–100, higher is better** (100 = category's best). The client renders this as "İlk %{100−p}". |
| `consistency` | `object \| null` | Multi-year consistency: `{ "beaten": <int>, "years": <int> }` — e.g. `{ "beaten": 4, "years": 5 }` → "Son 5 yılın 4'ünde kategorisini geçti". Counts the years the fund beat its **category median**. |

### Example (`GET /funds/AFT`)

```jsonc
{
  "fund": {
    "code": "AFT",
    // …existing fields…
    "ter": 2.15,
    "netReturn": { "y1": 48.3, "m3": 9.1 },
    "realReturn": { "y1": -6.2 },
    "categoryPercentile": 82,
    "consistency": { "beaten": 4, "years": 5 }
  }
}
```

## 2. Fund detail — allocation as-of date

`GET /funds/{code}?include=...,detail` currently returns `allocation` (the asset
breakdown). Add the date that breakdown was published:

| Key | Type | Meaning |
|---|---|---|
| `allocationDate` | `string \| null` | ISO date (`"2026-09-30"`) of the allocation snapshot. Rendered opposite the "Varlık Dağılımı" title as "{date} itibarıyla". |

It lives next to `allocation` in the detail response (sibling of `prices`,
`monthly`, `volatility`). The source column already exists server-side
(`fund_allocations.date`).

```jsonc
{
  "fund": { /* … */ },
  "allocation": [ { "label": "Hisse Senedi", "pct": 74.2 }, /* … */ ],
  "allocationDate": "2026-09-30"
}
```

## 3. Sub-year funds — since-inception return for list contexts

A fund younger than one year has no real `y1`; the feed currently carries a
misleading `0`. On the **fund detail page** the client already fixes this by
computing the return since inception from the price series. But **list contexts**
(compare board, goal/category pages, tables) have no price series, so they
cannot.

**Request:** for a fund without a full year of history, make the API express a
usable figure in list responses, one of:

- **Preferred:** have `y1` carry the **since-inception return** for sub-year
  funds (so ranking and display are correct everywhere), **and** add a flag
  `hasOneYear: boolean` so the client can label it "Kuruluştan beri" rather than
  "1 Yıl"; **or**
- add a dedicated `inceptionReturn: number \| null` plus `hasOneYear: boolean`,
  leaving `y1` as-is.

Either way the key signal the client needs is **`hasOneYear`** (or an
equivalent): without it, list rankings treat a two-month-old fund's `0` as a
flat year. The client's `hasFullYear()` currently infers this from
`inceptionDate`; a backend flag is more reliable.

## 4. Reference data (backend-internal)

- **TÜFE (CPI) monthly series** — required to compute `realReturn`. Internal to
  the backend; not exposed to the client. Keep it independent of any commercial
  partnership, per the strategy's independence guardrail.
- **Stopaj brackets** — the fund-type / holding-period table behind `netReturn`.
  Where the client must derive net itself (no `netReturn` present), it applies a
  flat `gross × (1 − stopajRate)` using the fund's published `withholdingTax`,
  which is only an approximation — the authoritative figure should come from
  `netReturn`.

## 6. Analytics (no endpoint — for the data team)

v2.1 adds three GA4 events (client-side, via the existing dispatcher). No API
work, but the funnel/baseline definitions live with the data team:

- `goal_entry_click` — `{ goal, location }`
- `category_page_viewed` — `{ goal, funds }`
- `compare_to_track` — `{ code, from: "compare"|"fund", compared: bool }` — **the
  north-star event.** Compare-to-track conversion = `compare_to_track` with
  `compared: true` as a share of sessions that fired `compare_fund_added`.
